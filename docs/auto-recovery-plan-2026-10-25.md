## 一、为何失锁后感觉只能手动定位

1. **失配暂缓自动提示，但识别仍在继续。** HEAD 中有效非填充词失配会锁存不可靠；静音 tick 要求 reliable 才能播报。后续成功匹配原本可以恢复，并非只能调用手动定位。参见 backend-core/app/domain/session.py 的 transcript 与 tick 分支，工作区约第 281、326 行。
2. **后续正确文字可能已经离开旧窗口。** ScriptAligner 默认前 40、后 80 个内容单位，实际还按片段长度调整，并有距离惩罚。噪声期间继续读，真实位置逐渐远离旧游标，后面的正确转写也找不到锚点。参见 backend-core/app/domain/tracking.py:219、355。
3. **HEAD 的 LLM 也只能看到附近窗口。** 实际朗读处不在输入内，换更强模型也无从选择正确位置。
4. **实时识别不等于实时定位。** api/session.py:483 通常直接返回 partial，只有 final 或静音截止结算 pending partial 才提交位置；连续朗读时确认游标可能滞后。

手动定位有效，是因为它直接更新锚点和可靠性。正确修复应让失锁状态持续利用后续正文寻找新锚点。

## 二、抗噪声现状

| 层次 | 已有能力 | 需要补齐 |
|---|---|---|
| 浏览器 | AEC、noiseSuppression、AGC；未提交改动新增可选 voiceIsolation 与 speech hint | microphone.ts:19 的约束均为尽力请求；增加 getSettings() 实效诊断 |
| PCM | 单声道 16 kHz PCM16、20 ms 帧 | pcm-capture.js 只有重采样，没有独立降噪 |
| 声学证据 | WebRTC VAD、去直流 AC RMS、连续帧门控 | 固定门限不适应不同底噪，能量兜底仍可能授权非语音 |
| 分段识别 | 无声转写过滤、迟到 final、云端与本地热备 | 同段修订复核、可选 ASR 质量信息、统一声音证据与超时 |

audio_evidence.py:23、86 中，即使 VAD=false，只要 AC RMS≥64 持续80ms，也可授权转写。独立探针输入80ms、±100交流波形，得到 confirmed_voice=false、transcript_allowed=true。这是轻声兜底的边界，不能仅提高统一门限，否则可能增加轻声漏检。

同文件约第120行对已接受段号直接放行。探针在接受一段后添加800ms纯静音，同段修订仍通过。应保留迟到 final 的原始声学归属，同时复核新增文字与新增时间范围，不能简单删除锁存。

speech_websocket.py:331、378 还使用独立 RMS 条件启动云端无结果超时；speech.py:701 后服务异常会在当前流切到本地。这是潜在质量波动来源，尚不能认定为用户现场失锁的唯一根因。

建议：

- 在可信非语音区间缓慢估计噪声底，用相对 SNR、VAD 和持续时间联合判断；避免将持续讲话吸收为噪声底。
- 区分确认人声、不确定声学活动、无有效证据；不能只因能量高就信任文本，也不能只因文字短就认定是噪声。
- 保留弱声、短词、句首缓冲和尾部静音，维持 ASR 连续时间轴。
- 限制能量兜底的权限；有声但无可靠文字继续待确认，不强制恢复位置。
- 给 RecognitionUpdate 增加供应商可提供的可选置信度、词稳定性等字段；没有时保持缺省。
- 用目标设备对照决定是否增加一种轻量降噪器或更强 VAD，同时验证与浏览器处理的组合。
- 旁人真实讲话需要拾音方向、近讲距离或额外主讲人校验，不能承诺靠能量门限排除。

## 三、未提交恢复改动的具体问题

已有改动增加前160、后512单位且最多4096字符的恢复窗口、六单位以上原文/拼音锚点，以及 LLM 文本证据检查。这些可保留为起点，但存在：

1. api/session.py:179 缺少 content_units 导入，开启 LLM 且失配时可能异常。
2. domain/session.py:314 将所有1～5单位失配沿用旧可靠性，无法区分真实脱稿与噪声。已有测试出现本应暂缓时从旧位置自动播报。
3. 会话先走普通 align，成功就绕过 recover 的唯一性检查。稿件“开场。大家好欢迎回来。大家好欢迎回来。大家好欢迎回来。”中，align 接受第一次出现，recover 则拒绝歧义；新增测试因此失败。
4. 固定后512单位仍无法覆盖全稿。将唯一目标放到600个填充单位后，recover 返回 None。
5. 一次足够长的局部失配就触发扩大恢复，没有要求独立证据确认大跳。背景话语恰好符合远处稿文时可能拉动游标。
6. api/session.py:392 仅避免 VAD 起落取消 LLM；:453 的新 partial 修订仍取消任务，连续说话可能一直等不到恢复结果。
7. recovery=true 被传入领域层但未读取。模型引用再次当作转写进入匹配，恢复权限和歧义语义没有统一入口。
8. 界面“继续朗读一小段讲稿将自动重新定位”过于确定，应显示“正在尝试自动重新定位”及等待原因。

不能只补导入、修改失败断言就发布。

## 四、推荐定位设计

处理顺序：

PCM/ASR → 声学与分段版本校验 → 局部跟踪 → 扩展邻域 → 全稿候选检索 → 歧义和连续性确认 → 更新可靠位置 → 按原静音规则自动提示。

### 位置与状态

- 保留现有 reading/prompt 双游标；增加临时跟踪位置。稳定 partial 可更新临时高亮，自动播报只使用确认位置。
- 最后确认位置与本轮可靠性独立保存：待确认不抹掉历史搜索锚点，也不把历史锚点直接当作当前可靠位置。
- searching、ambiguous、provisional 等属于对齐诊断，不增加五状态机主状态。失锁期间保持 LISTENING；真正断流或服务故障仍按原规则 PAUSED。
- 无 final 时保留静音截止结算 partial 的能力。将它标为可被同段修订撤回的稳定证据，避免临时位置永远不能确认。
- 证据身份包含流实例、generation、segment_id、文本版本和结算来源。空 final/填充词撤回旧候选；重复 final 不重复推进。

### 渐进恢复

- 正常朗读采用有界局部模糊匹配。
- 失锁后扩展邻域；仍失败则用预建规范字、拼音和 n-gram 句段索引，从全稿召回少量候选。
- 检索在音频控制锁外运行，限制候选数、输入长度、耗时及历史缓冲。
- 普通匹配、扩大搜索与模型候选共用恢复验证，避免普通路径绕过歧义门槛。
- 比较第一、第二候选分差，并用后续独立片段验证位置方向与连续性。重复句等后文消歧，大跳要求更强证据。
- 同一段重复 partial、partial→final、重复 final 不能当作多份独立证据。
- 人工定位后重置旧搜索状态，防止旧候选拉回游标。

### 统一提交

增加类似 apply_alignment_candidate 的入口，接受候选位置、原始证据、来源与证据版本，校验后同时更新 reading/prompt 游标与可靠性。恢复成功清除本次失锁提示；按原静音条件重新允许自动播报。

若仍在讲话，继续等待实际静音；若已有符合原规则的完整静音，可正常进入提示。无需再次手动定位。

## 五、大模型的合适位置

项目已有 off/fallback/hybrid 与文本校准接口，见 backend-core/app/infrastructure/llm.py:127。它接收文字，没有音频，因此适合文本纠错和候选筛选。

建议先用 **fallback**：本地无法可靠定位且已有充分有效文字时调用。输入少量带句段ID的候选及短期转写证据；输出候选ID、原文span，或明确无匹配。相同句子不同位置必须使用不同ID。

模型 confidence 仅作参考。服务端仍检查字面/拼音支持、原文范围、候选歧义与前后文连续性；高置信但无原始证据的引用必须拒绝。

调度需做到：

- 请求绑定不可变的已结算证据版本，partial 仅更新临时位置，避免不断取消请求。
- 返回后使用其后的 final 追赶验证，提交当前实际位置；缺少后续历史或验证超预算则丢弃。
- 人工定位、暂停、播报切换、断流、流重建和 generation 变化使旧请求失效。
- 去重、限频、失败退避、超时保持有界；模型失败不影响继续本地识别。
- 界面显示等待正文、搜索中、候选歧义、模型不可用和已恢复；诊断保留安全的次数、原因与延迟。

## 六、实施顺序与验收

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| P0 恢复闭环 | 修复异常与测试替身；明确短失配语义；统一候选验证；局部→扩展→全稿 | 噪声失锁后继续读可自动恢复，重复句和无关文字不乱跳 |
| P1 实时与抗噪 | 临时/确认位置、稳定partial、实际音频设置诊断、自适应声音证据、修订复核 | 连续朗读持续跟踪，真实噪声误失锁下降，轻声无明显退化 |
| P2 可选LLM | 候选ID重排、拒绝分支、任务追赶、节流与诊断 | 连续朗读时恢复请求可完成，模型不可用仍持续本地恢复 |

必须补充的自动化场景：

1. 可靠朗读→噪声→失锁→继续读→窗口外恢复→静音自动提示，全程不手动定位。
2. 600单位以上跳读、回读、英文和数字完整边界。
3. 重复句先保留歧义，后文出现后恢复正确段落。
4. 1～5单位真实脱稿与背景噪声分开；连续短失配不能无限沿用旧可靠性。
5. 无final、稳定partial、同段改写、空final、填充词撤回、重复final去重。
6. LLM期间连续partial；近音纠错成功；无证据高置信引用拒绝；超时/格式异常不阻断本地恢复。
7. 暂停、人工定位、断流及流重建后，迟到ASR/LLM不能覆盖新位置。
8. 保留持续静音帧与真正无帧断流的区别，以及既有5秒断流保护。

目标设备验收需覆盖风扇、键盘、音乐、旁人讲话、回声、轻声、远讲及不同噪声强度。现有方波、数字静音和模拟ASR仅验证控制链路。

至少记录误失锁率、错误跳转率、充分正文后的恢复成功率、恢复延迟P50/P95、轻声漏检率、实际识别源和LLM调用量。先建立设备基线再确定量化目标；本方案没有把模拟结果当作真实准确率。

完整实现通过回归和目标设备验收后，再构建与切换镜像。
