# 抗噪与失锁自动恢复实现记录

日期：2026-10-25。修复前审查见[方案快照](auto-recovery-plan-2026-10-25.md)。

## 用户可见行为

- 定位失败后继续监听并尝试恢复。正常朗读使用附近匹配；失锁时使用预建全文字面/拼音trigram索引，不再受旧位置后512单位限制。
- 附近唯一正文可直接恢复；远处候选须两份独立、连续、各不少于6个内容单位的证据确认。同段partial/final、相同文字重复、LLM纠错不算独立证据。
- 重复句显示等待消歧，后文可确认具体段落；不只按离旧游标近就解除失锁。
- partial两次相同或保持300ms后显示蓝色虚线临时高亮，不改变确认朗读/提示起点、不授权自动播报；final或原有静音截止结算才提交。
- 恢复后按原静音条件自动提示。可信人声无法定位时保留AC-14，1～5单位真实失配也不能沿用旧可靠性强行播报。

## 抗噪改进

AudioEvidence在连续600ms、VAD阴性且能量变化不超过12%的窗口学习平稳底噪。纯能量兜底要求AC RMS同时达到64和底噪的1.5倍；VAD阳性保留原AC RMS 16、连续60ms的轻声通道。

学习到平稳噪声后，撤回该窗口早期仅凭能量获准的partial。Runtime在预览、静音结算与模型回包前使相关临时证据失效，避免被撤回文字再推进游标。连续PCM时间轴、尾部定稿及5秒无帧断流保护保留。

已授权分段的迟到final可包含原声学锚点及尾静音；如果时间范围迁到后续无声区间，需重新取得声音支持。无时间戳供应商仍沿用原有保守归属。

浏览器继续请求回声消除、降噪、自动增益，支持时附加voiceIsolation与speech hint。可选getSettings()记录实际处理设置，仅保存在内存，不含设备标识；请求成功不等同于硬件实际启用。

## 大模型辅助

保留off/fallback/hybrid，建议先用fallback。无需大模型也可进行全文恢复。

失锁请求按有效文字从全稿召回最多4段原文，总上下文不超过4096字符；正常可靠匹配仍用附近窗口。输出仍为matched_quote和confidence，服务端检查至少6完整单位、原文子串、字面/拼音证据和领域恢复规则。模型不能提供游标或仅凭高置信放行不相关内容。

任务绑定已结算证据版本及流epoch。新partial不反复取消请求；最多追赶4条后续结算证据。回包在副本中重放验证，再更新真实会话。人工定位、暂停、播报、流重建、同段修订/撤回使相关旧返回失效；不会覆盖已确认新位置。旧回包也不能替新一轮未结算声音放行自动提示，当前活动仍保持pending。

当前保留quote协议，通过全文唯一性与跨段证据消歧；未增加候选ID模型协议、神经降噪依赖或ASR置信度字段。

## 快照

| 字段 | 含义 |
|---|---|
| provisional_position / provisional_transcript / provisional_confidence | 稳定partial临时结果，位置可为null |
| recovery_status=idle | 无待处理恢复 |
| recovery_status=searching | 等待正文锚点 |
| recovery_status=ambiguous | 存在多个位置，等待后文 |
| recovery_status=confirming | 已有远处候选，等待独立后续片段 |
| recovery_attempts | 尝试次数，手动定位后清零 |

这些是对齐诊断，五状态机与双游标定义不变。前端兼容缺少新字段的旧快照。临时位置不触发确认位置跟随或全文完成提示。

## 部署与边界

源码和测试不等于8080服务已更新。本轮不替换正在使用的容器、不改变模型凭据。结束演讲并按运维手册备份后，在根目录执行：

```bash
docker compose build && docker compose up -d --force-recreate --wait --wait-timeout 180
```

刷新工作台创建新会话，无需重填API Key。其他服务器需重新制作离线包。

强背景人声、音乐、突发非平稳噪声、VAD误判及ASR错误仍有边界。底噪学习需600ms，早期错误final可能短时影响位置；对应声音证据一旦撤回，立即取消位置可靠性和整条依赖链，保留旧偏移作历史而不猜测回滚。长时间VAD漏检的稳定弱声仍需设备验证。重复段正文不足时继续等待，有声无可靠文字时仍pending；模型超时采用本地恢复，不猜位置。

本轮未采集用户麦克风、调用付费模型或完成新的真实云端中文准确率、目标设备长时抗噪验收。
