# 运维手册

## 日常与更新

```bash
curl -fsS http://localhost:8080/api/health
curl -fsS http://localhost:8080/api/speech/status
docker compose ps
docker compose logs --tail=100 backend frontend
```

顶栏诊断区分后端能力、WebSocket、麦克风和最近播放结果。`tts=ready` 仅表明依赖可用；真实合成或浏览器播放失败需单独处理。常规轮询不调用付费模型、不录音、不自动试听。

保留数据目录后更新：

```bash
docker compose build && docker compose up -d --force-recreate --wait --wait-timeout 180
```

更新前备份讲稿与私有配置。容器重启丢失实时会话，讲稿和已激活模型配置仍从挂载加载。不要删除 `data/sqlite` 或 `data/backups`。

## 讲稿备份与恢复

在项目根目录执行：

```bash
python3 scripts/backup.py data/sqlite/whisper-guide.db \
  data/backups/whisper-guide-$(date +%Y%m%d-%H%M%S).db
```

脚本使用 SQLite backup API 和 quick_check，不覆盖同名目标。目标目录必须对执行用户可写，容器 UID 为 10001。数据库备份不含录音，也不含下述模型方案。

恢复前停止 backend、保留当前数据库副本，验证备份 quick_check，再替换 `whisper-guide.db`。不要在 SQLite 仍有写入连接时覆盖文件；恢复后检查 `/api/scripts`、`/api/health` 和语音状态，重新准备演讲。

## 模型方案备份与迁移

当前文件 `data/sqlite/.model-configs.json` 包括全部方案、密钥和独立生效快照；旧兼容文件为 `.model-settings.json`。两者均按敏感凭据保护，权限 `0600`，只备份到受限目录，不进入 Git、发布包或日志。

首次升级读取旧配置并生成“现有配置”和无凭据的“默认本地离线模式”；新仓储落盘后以其生效快照为准。迁移时保留新仓储整份文件、所有者和权限，停止 backend 后恢复并重启。只恢复 SQLite 不会恢复模型方案。

编辑不改变生效版本，保存后需主动激活。测试使用未保存草稿，不改写文件或生效状态。凭据留空保留，新值替换，明确清除才删除；复制方案不复制凭据。修订冲突返回 409，应保留本地草稿并刷新比较。

配置损坏时显示仓储不可用。先停止服务、保留损坏文件，再从受限备份修复，不要直接删除私有文件解除错误。503 保存失败时检查磁盘余量和 UID 10001 的目录写权限。

## 断线会话恢复与配置激活

工作台提供恢复/明确结束入口，避免浏览器刷新遗留暂停会话阻止激活。恢复不自动打开麦克风或播放音频，之后由用户开始或继续。

```bash
curl -fsS http://localhost:8080/api/sessions/recoverable
```

只列出无连接且未终止的会话元数据：`session_id`、`script_name`、`state`、`config_name`，不返回正文或识别文本。明确放弃某会话时指定 ID：

```bash
curl -fsS -X POST http://localhost:8080/api/sessions/<session-id>/terminate
```

已被其他页面连接的会话返回 `409 SESSION_CONNECTED`，需在所属工作台结束；不存在返回 404。接口不会自动结束在线会话。所有未终止状态（包括 READY 与 PAUSED）都会使模型激活返回 `409 SESSION_ACTIVE`；恢复后继续或明确结束即可解除。

## 识别状态下的静音自动提示

在工作台选择讲稿，设置“静音等待”（整数，最小 1000 ms），再点击“开始演讲”。浏览器确认麦克风就绪（`audio_ready`）后开始计时；保持麦克风开启但不讲话，到期应从“识别”切换为“播报”。播完回到识别，麦克风重新就绪后开始下一轮等待；只推进提示游标，不把提示内容当成用户已朗读内容。

音频处理结束且队列清空时会立即检查截止时间，50 ms 周期检查仍保留。排队的人声优先处理；旧轮次或已失去 WebSocket 归属的处理结果不能触发新轮提示。连续静音帧属于正常采集；超过 5 秒收不到帧属于麦克风断流，会暂停而不是自动播报。不能通过停止采集来模拟正常静音。

如果等待后仍不播报，先看顶栏麦克风、连接与播放状态，再看“状态机与流转诊断”的触发原因：

- 未允许麦克风、切换页面或设备断流：恢复连接/设备后点击“继续演讲”。
- 定位不可靠：继续朗读可匹配的讲稿，或手动定位恢复可靠起点；自动提示不会使用不可靠游标。
- 已进入播报但无声：检查最近播放结果、耳机/系统输出与 TTS 网络，查看是否因合成/播放失败而暂停。

详细用例、数字静音原生模型检查与亮暗截图见[静音与状态图验收记录](silence-state-2026-10-24.md)。更新现有容器按本手册的构建命令操作。

云端场景还需查看原始文本是否正在修订、讲稿匹配是否可靠。界面会显示“等待有效识别文本/定稿”或“自动提示已暂停”；同段修订现在可以再次结算。持续 VAD 人声会取消静音等待，音量较低但 VAD 检出的人声也会启动云端无结果超时并允许回退本地。方舟文本请求超时不会阻塞音频控制锁，但无法替失配片段恢复可靠位置。本轮实际 STT/TTS 与文本延迟检查、完整回归见[云端静音排查](cloud-silence-2026-10-24.md)。

## 读完段落却只提示末字

自动提示依讲稿中的真实分段边界计算，而不是屏幕自动换行。可靠读到标点或空行前的最后单位后，下次提示从下一片段开始；片段中间停顿仍重复一个完整单位作上下文。全文完成时保持识别并显示“已到讲稿末尾，不再自动续播”，可结束、回读或手动定位。

例如读完“认真奔赴目标。”，下一次提示应为“我会坚持自律，”；若匹配结果只到“遇到困难”，后文“不轻易放弃”之间没有边界，则仍是句中停顿，不应据此越过整句。已经实际读完但匹配落后，需继续核对有效原始转写与讲稿匹配，不能用跳段代替可靠定位。

手动定位表示明确指定下一次提示起点，仍从选定单位播放；暂停、打断后也保留该次提示片段起点。修复记录与截图见[提示起点验收](prompt-boundary-2026-10-24.md)。

## 识别在持续使用后变乱

先分别看“实时识别”“讲稿匹配”和顶栏实际识别来源。原始 ASR 出错、原文长句对齐失败、云端保护性回退属于不同问题，不应只调整 Key 或静音等待。

本轮修复长句被误判远跳，以及每块发送额外累计网络耗时造成缓冲增长的问题。背景噪声仍可能进入 ASR：VAD 不是完整噪声隔离；接收侧已加入并验证声学证据门控，需重建镜像后生效，详见[验收记录](noise-guard-2026-10-24.md)；不能把升级后的模拟测试解释为任意真实环境均不会误转写。外放/自动增益的影响需用目标设备验证，先用耳机、稳定话筒距离和相对安静环境对照。若出现“识别已回退本地”，记录发生时的来源提示即可，不要保存或贴出用户录音和密钥。

完整代码依据、确定性节拍与长句回归、抗噪边界见[连续识别排查记录](asr-drift-2026-10-24.md)。

## 大模型连通性测试失败

“未完成连通验证”是旧界面对失败结果 `verified=none` 的模糊描述，不代表没有执行测试。新版失败标题为“连通性测试失败”，后端返回受控 `error_code`；HTTP 拒绝另含整数 `http_status`。不返回服务商原始正文、异常文本、URL 或请求头，避免凭据回显。

| 诊断 | 优先检查 |
|---|---|
| HTTP 400 | 模型参数及 Chat Completions 协议兼容性 |
| HTTP 401 | API Key 是否有效、是否属于所配置服务 |
| HTTP 403 | 模型开通、项目权限、账户状态 |
| HTTP 404 | Base URL、实际 Model ID/接入点 ID、当前密钥是否有权限访问模型 |
| HTTP 429 | 额度、余额、限流状态 |
| HTTP 5xx | 服务商暂时异常 |
| TIMEOUT | 超时阈值及服务器网络 |
| NETWORK_ERROR | 服务端 DNS、代理、HTTPS 证书与连接 |
| INVALID_RESPONSE | 是否为兼容的 Chat Completions 响应 |

测试返回耗时明显小于设置的超时值时，不能只凭“连接失败”断定超时。选择“自定义”预设不会改变 HTTP 协议；预设只填充地址和示例模型名。API Key 已保存也不证明它具备目标模型权限。

2026-10-24 在运行后端内用已保存的方舟凭据及截图的草稿模型 `doubao-seed-2.1-lite` 复现一次最小请求，实际返回 **HTTP 404 / InvalidEndpointOrModel.NotFound**，并非超时。该结果只能证明这次请求找不到或无权访问目标模型，不能断言该名称对所有账号都不存在。请从目标模型的 API 调用示例复制 `model` 值，确认同项目密钥具备权限，再重新测试、保存并激活。不要使用 API Key 资源 ID 代替模型 ID。

本次复现只请求短文本，未发送演讲稿或录音，未修改现有模型方案；验证尚未成功，不能记为真实豆包验收通过。后续修复代码需重新构建镜像才会在现有容器生效。

回归记录：[后端](validation/2026-10-24-llm-diagnostics-backend.txt)、[前端](validation/2026-10-24-llm-diagnostics-frontend.txt)。后端 232 项、前端 13 项 Node + 23 项 Vitest 全通过，Ruff 静态/格式检查及类型检查、生产构建通过。未再次运行浏览器端到端或重建镜像。

## 原生流式语音配置与诊断

语音 STT 和方舟文本 LLM 是两条独立链路。原生语音选择 `volcengine-ws`，推荐地址为 `wss://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`，ASR 2.0 小时版资源为 `volc.seedasr.sauc.duration`，请确认账号已开通。新 `api-key` 模式不填 App ID，凭据栏填写**语音服务 API Key**；旧 `app-token` 模式填写 App ID 和语音 Access Token。不能假定创建方舟文本 Key 后就有语音权限，后端不会自动借用文本密钥。

语音请求超时默认 `5000 ms`，范围 `200–30000 ms`，与 LLM 的 `llm_timeout_ms` 独立。二次识别开关只作用于 `bigmodel_async`，普通 `bigmodel` 不启用该功能。先分别测试语音、文本，再保存并激活；暂停状态仍阻止激活。

| 语音测试结果 | 处理 |
|---|---|
| `CLOUD_OPT_IN_REQUIRED` | 明确勾选音频云端授权后再测试 |
| `CONFIG_INCOMPLETE` | 核对协议、WSS 地址、资源 ID、语音凭据及旧模式 App ID |
| `HTTP_ERROR` | 检查握手 HTTP 状态、资源开通、鉴权模式和账号权限 |
| `PROVIDER_ERROR` | 按受控数字业务码核对语音资源、账户与请求格式；不输出原始正文 |
| `TIMEOUT` / `NETWORK_ERROR` | 检查服务端 WSS 网络、DNS、证书和代理，必要时调整独立语音超时 |
| `INVALID_RESPONSE` | 确认是火山 ASR v3 二进制协议端点，非方舟 Chat Completions |
| `probe_empty_audio=true` | 静音探测收到已知 `45000002` 空音频结果，只证明鉴权/协议可达；转到工作台真实朗读 |

探测必须等音频结束后的最终包，只有握手或初始化 ACK 不算成功。生产识别若断网、超时或超出有界缓冲会回退本地；工作台显示的当前识别源可能因此与所选云端方案不同。不要将云端配置存在、本地模型 ready 或静音协议探测成功记录为云端识别准确率通过。

传输每 200 ms 发送 16 kHz 单声道 PCM16，音频缓冲最多 1 秒、结果最多 32 项、WebSocket 传输最多 4 个活跃线程。暂停/终止会取消连接和丢弃迟到结果，服务不会持久化录音。公网必须 WSS，禁止 URL 凭据/查询/片段及重定向。语音服务数据保留政策由服务商决定，应用的“不录音落盘”不等于云端不处理数据。

本轮只用本地 WebSocket 模拟服务完成自动化验证，尚无真实 ASR Key、真实语音网络调用或真实中文准确率验收。补齐凭据后应验证正常朗读、回读、填充词、网络回退与提示音，分别记录实际结果。

## 从接口选择模型

在模型配置页填写 Base URL 和 API Key，点击“获取模型列表”，按名称或 ID 筛选后从下拉列表选择。已有方案的密钥可留空复用；没有密钥要求的本地服务可留空。未开启语义对齐、尚未填写模型名和新建未保存方案也可以获取列表。

获取列表和选择都不保存、不激活；选择后测试大模型连通性，通过后保存并激活。服务不支持列表、返回空列表、超出响应限制时仍可手填模型 ID。接口返回的目录并不保证当前密钥具备每个模型的生成权限。

列表请求经后端发送到当前 Base URL；编辑地址前确认目标服务，已有密钥也会被发送到该目标。修改地址、密钥、清除状态或预设会取消旧请求并清空旧列表；换方案或离开页面也会取消，迟到结果不能覆盖新草稿。

2026-10-24，新发现实现通过一次只读方舟请求获取 137 个模型，479 ms，未截断。只读临时容器复用现有数据及源码的只读挂载，执行后自动清理；未调用文本生成、未发送讲稿/录音、未变更原方案或运行服务。该结果不代表 137 个模型全部完成生成接口验收。详见[模型发现实现与验收](model-discovery-2026-10-24.md)。

## 开发与构建缓存清理

先区分可再生缓存与运行数据：`data/sqlite`、`data/backups`、私有模型方案、当前使用的四份 STT 权重都需要保留。`.venv` 与 `frontend/node_modules` 是正在使用的开发环境，不因体积较大就删除。缓存清理后首次依赖同步或构建可能需要重新联网下载。

在 WSL 项目根目录按需执行：

```bash
# 查看占用和 Docker 缓存，先判断是否有正在执行的构建。
du -sh backend-core/models backend-core/.venv frontend/node_modules
du -sh "$(uv cache dir)"
pnpm --dir frontend store path
docker system df
docker buildx du

# 移除可再生依赖下载缓存，保留已安装开发环境。
uv cache clean
pnpm --dir frontend store prune

# 清理指定 builder 中超过 24 小时未用的构建缓存。
# 该缓存可能与其他项目共享；执行前确认可接受下次重建。
docker buildx prune --filter until=24h
```

不要把 `docker system prune -a --volumes` 当作本项目维护命令；它会影响其他镜像、容器或卷。运行中的服务继续引用旧镜像层，构建完成不会自动释放这些层，也不会自动更新现有容器。结束演讲、完成备份后再按本手册执行容器更新。

本地模型目录已完整时，可在 `backend-core` 执行 `uv run python scripts/download_asr_model.py` 离线清除冗余权重、官方测试样本与本模型固定名称的残留归档。脚本只在四份核心文件完整时清理，下载失败保留断点；不要手工按通配符删除 `.onnx`。Docker 运行镜像不包含下载脚本，应在构建机源码目录执行。

本轮实际移除 uv 缓存 6.6 GiB、pnpm 孤立缓存 189 MB，以及 152 条 Docker 构建缓存（工具报告 10.85 GB）；后续构建会重新产生缓存。这些统计来自不同工具，可能含共享文件或不同计量口径，不直接累加成物理磁盘释放量。WSL/Docker 虚拟磁盘内部释放空间也不代表 Windows 的 VHDX 文件立即缩小。本轮没有执行虚拟磁盘压缩、数据卷删除或用户服务重启。详见[瘦身记录](storage-slim-2026-10-24.md)。
