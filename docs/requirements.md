# 行为规范

合并原需求基线，保留AC-01至AC-27编号；AC-28起补充进度提示和手机验收。使用见[使用指南](user-guide.md)，实现见[架构](architecture.md)，验证见[测试指南](testing.md)。

## 范围与存储

面向中文为主、夹杂英文数字的照稿演讲，允许少量口误、重复和插话，不保证大量改述或即兴演讲定位。

浏览器负责采音、传输、播放与交互，服务端执行VAD、ASR、对齐和TTS，不是浏览器独立离线工具。每场演讲绑定一份讲稿，换稿先结束会话。

讲稿在SQLite持久保存；麦克风录音、切片、Base64与提示音频不写文件、数据库或日志。会话只在内存，服务重启后重新准备。

上传接受.txt/.text/.md纯文本，不执行Markdown。支持UTF-8（含BOM）、带BOM的UTF-16与GB18030；默认每份2MiB、每批10份。一份不合格整批不保存，同名文件保留独立ID，不覆盖原文。未使用稿可经确认删除，成功清选择与预览，失败保留条目。任何未终止会话引用时拒绝（含READY、PAUSED及断线），暂停不解除保护；其他未用稿仍可删。删除与准备会话原子化，不改变已有快照。

## 内容与位置

中文按字符、英文按完整单词、数字按连续单位（含支持的小数/版本/百分比），不能从单词或数字内部提示。

reading_position只由可靠用户语音更新；prompt_position为下一提示起点，系统播报不推进reading_position。静音模式句中停顿保留最后完整单位作上下文；进度模式在位置可靠时从下一完整单位开始。定位未确认时，两模式均使用保存的提示起点。读完分段则从下一片段开始，全文完成不重复末字。

支持回读；重复句需上下文消歧，不能因系统曾播到后文强制用户位置向前。稳定partial仅显示临时位置，不直接提交游标；进度模式可用有声学依据且稳定的向前partial延后接管，实际播报前仍须结算。

## 状态与计时

| 状态 | 行为 |
|---|---|
| READY | 等待开始，不识别、播报或计时 |
| LISTENING | 接收语音，跟踪位置与静音 |
| PROMPTING | 停止识别和计时，生成播放提示 |
| PAUSED | 停止识别、播放和计时，保留位置 |
| TERMINATED | 释放本场资源，不能继续 |

对齐诊断与临时位置不增加主状态。silence_timeout_ms默认3000，须为>=1000整数，只在READY/PAUSED修改。开始、继续、正常播完、打断后重新等待完整阈值，暂停时长不累计。

开口优先取消静音等待，停声后计时。首次未开口从已知讲稿开头提示；超过5秒无帧为断流，进入暂停。

静音模式自动提示要求LISTENING、收音已就绪且实际音频持续到达、待处理音频已结算、没有当前人声、达到静音阈值、有剩余内容且服务可用。优先结算有效识别草稿；位置仍pending/mismatch时从保存的prompt_position播报，并明确提示未确认位置，不改reading_position或可靠性。片段到下一个中英文逗号、句号、问号、感叹号、分号或空行；小数点不分段，单换行为软换行，连续标点不产生空片段。

正常播完由浏览器实际完成通知确认，只推进prompt_position；静音模式仍沉默则再次等待并提示。手动打断立即停声并作废旧音频，恢复识别；仍沉默时重播被打断片段。播报时开口不会自动打断，也不作为进度。

暂停/故障保留进度，服务恢复不自动继续；播报中暂停后继续也先识别，不续播旧音频。结束使旧识别、合成、计时与播放通知失效。

同批事件：结束 > 暂停/故障 > 手动打断 > 用户开口/识别 > 播放完成 > 到期。静音模式开口取消静音；进度模式仅有声而没有有效进展不会无限取消接管。

### 进度超时提示

`prompt_mode=progress`为用户主动选择的辅助模式，默认仍为`silence`。`progress_timeout_ms`默认4000，严格整数2000–10000。计时从实际收音开始；可靠讲稿向前推进或有声学依据且稳定的向前partial更新进度。重复结果、无关转写、同位置修订、填充词和单纯VAD活动不重启计时；暂停、播报期间不累计。

到期先结算已接受草稿，结算确有新进度则重新等待，否则从可靠位置的下一完整单位、或未确认时的保存提示起点播报一段。该模式允许在持续声音下接管，可能插入慢读或改述，界面必须说明。设备断流、尚未就绪、处理积压和全文末尾始终禁止自动接管；不等待LLM决定倒计时。

默认`continuous_prompt=false`时，进度模式每次停滞只自动提示一段，正常播完后等待新的有效朗读进度。开启持续代读后，每段结束、重新收音就绪并等待完整周期才继续。手动提示、再等一下、重新定位和用户主动继续可重新开始辅助；播报失败或旧回调不推进游标。`postpone_prompt`在识别中重新等待完整阈值，不伪造朗读位置。

### 手机工作台

320px起保持可读、无页面横向溢出；讲稿正文与暂停/继续、立即提示、打断播报为主要操作。低频模式/阈值/定位集中到适应视口的设置面板，结束须确认；诊断和识别详情可折叠。主触摸目标不少于44px，底栏预留安全区且不遮挡正文。后台/页面离开与音频中断安全暂停，回前台不自动恢复采音或播放。

## 定位与恢复

失配保持监听并尝试恢复，每次进入异常反馈一次；真实静音到期则从保存提示起点继续播报，另给出位置未确认提示，不把超时视作定位恢复。允许手动提示与定位。

失锁后持续全文检索，附近唯一正文可恢复；远处候选需两份独立连续证据，重复句等后文。模型引用、同段修订和重复文字不算独立第二证据。

声学证据撤回使依赖它的可靠性及暂定链失效，不猜测回滚。迟到模型不能覆盖人工位置、已确认新位置或替新待结算声音放行。有声无可靠文字保持pending，过滤/超时不强制恢复。

全文结束不自动终止，仍可回读或结束；系统播完不等于用户读完。核心流程须全键盘操作，按钮名称明确，反馈不只依靠颜色。快捷键与设备限制见使用指南。

## 行为验收基线

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 就绪状态等待超过阈值 | 不识别、不自动播报 |
| AC-02 | 点击开始后一直未开口 | 识别就绪后等待阈值，播报第一段 |
| AC-03 | 静音未达到阈值就恢复说话 | 取消倒计时，不自动播报 |
| AC-04 | 用户读到片段中间后停顿达到阈值 | 包含最后已读单位，播报至下一分段标点 |
| AC-05 | 停顿前最后单位为英文单词或连续数字 | 片段中间从完整单位起点提示，不截断；若单位正好结束片段则从下一片段起点提示 |
| AC-06 | 正常播完后一直沉默 | 每次完整等待阈值后播报下一片段，用户朗读位置不变 |
| AC-07 | 等待合成或播放期间手动打断 | 立即停止当前播放并作废后续音频，进入识别 |
| AC-08 | 手动打断后未开口 | 等待阈值后从被打断片段起点重播 |
| AC-09 | 从识别或播报状态暂停 | 停止识别、声音和计时，保留对应位置 |
| AC-10 | 静音 2500 毫秒后暂停，阈值为 3000，稍后继续 | 重新等待 3000 毫秒，不继承暂停前静音时长 |
| AC-11 | 播报中暂停后继续 | 进入识别，不直接恢复播放；沉默达到阈值后重播本次片段 |
| AC-12 | 在就绪或暂停修改阈值 | 合法正整数生效；非法值被拒绝；识别和播报期间不允许修改 |
| AC-13 | 用户口误、少量插话、回读或遇到重复句 | 结合上下文追踪；未确认位置不猜新游标，静音到期按保存提示起点播报并说明 |
| AC-14 | 持续定位不可靠 | 保持识别与恢复；静音到期按保存提示起点播报，可靠性仍为未确认，允许手动定位 |
| AC-15 | 暂停后收到旧音频，或打断后收到旧播放完成通知 | 不重新出声，不错误推进位置 |
| AC-16 | 暂停与超时同时发生；用户开口与超时同时发生 | 分别按暂停、用户开口处理，自动播报不获优先权 |
| AC-17 | 网络或语音服务故障，随后恢复 | 进入暂停并保留进度；恢复后等待用户主动继续 |
| AC-18 | 系统播到全文末尾 | 停止自动续播，不循环；用户仍可继续识别或结束 |
| AC-19 | 在任意未终止状态结束 | 终止全部活动；旧回调无效，本次会话不能继续 |
| AC-20 | 使用键盘操作核心流程 | 可完成开始、暂停、继续、打断、结束确认和阈值配置 |
| AC-21 | 一次上传多份有效纯文本文件，或分多次上传 | 各文件独立保存并出现在讲稿库；刷新后仍可读取 |
| AC-22 | 从讲稿库选择不同讲稿 | 每次只能选择一份，预览和本次准备使用的讲稿一致；未选择不能开始会话 |
| AC-23 | 上传同名讲稿 | 保留多份独立记录，不覆盖已有正文 |
| AC-24 | 一批中包含空白、二进制、超限或不支持格式的文件 | 明确反馈原因，整批不保存，不影响已有讲稿 |
| AC-25 | 上传含中文、英文、数字、换行的支持编码文本 | 正确解码并保留正文、标点和换行；不执行或渲染正文中的 HTML |
| AC-26 | 开始会话后暂停、继续或希望更换讲稿 | 原会话保持绑定同一份讲稿；换稿需结束原会话 |
| AC-27 | 实时音频处理、暂停、断网和结束 | 用户麦克风音频不写入持久存储或日志；不再需要的临时音频缓冲被释放 |
| AC-28 | 持续背景声且无有效进度，启用进度模式 | 实际收音正常时按进度阈值接管，不被VAD永久阻止 |
| AC-29 | 长句稳定partial持续推进 | 延后进度提示，仍不提前提交用户游标 |
| AC-30 | 重复/无关结果反复变化 | 不无限延长进度等待，不伪造定位 |
| AC-31 | 进度模式位置可靠或未确认 | 分别从下一完整单位或保存起点播报，显示原因 |
| AC-32 | 进度模式播完且未启用持续代读 | 不自动读完整篇；新有效进度或人工操作后重新辅助 |
| AC-33 | 再等一下、边界暂停、断流及积压 | 延后不移游标，暂停/故障优先，旧任务不出声 |
| AC-34 | 手机竖屏/横屏、长标题、面板和大字体 | 主要操作可触达、无横向溢出、正文不被底栏遮挡 |
| AC-35 | 手机切后台/页面离开后返回 | 安全暂停，需用户继续后恢复，不自动开麦或播放 |

自动恢复、声学门控、模型追赶与临时位置另有专项回归，见测试指南。毫秒参数不代表触发精度承诺，真实中文准确率、设备抗噪及读屏组合仍须现场验收。
