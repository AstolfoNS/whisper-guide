当前检查命令统一维护于本文，开发环境见[开发指南](development.md)。测试覆盖与实际设备验收分开，不把ready、数字静音或模拟服务当作中文准确率。

## 自动化检查

后端：

```bash
cd apps/backend-core
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

前端：

```bash
cd apps/frontend
pnpm test
pnpm typecheck
pnpm build
```

Chromium集成：

```bash
cd apps/frontend
# 仅首次需要，已安装时跳过
pnpm exec playwright install --with-deps chromium
pnpm test:e2e
```

## 静音到期、噪声与积压回归

静音策略回归覆盖pending/mismatch/no-text、证据撤回、真实声音优先、阈值前不播、EOF、旧代通知、播放后仅推进提示游标。到期从保存起点提示使用recognition_wait_timeout，不改reliable、reading_position、aligned文本或恢复证据。原依赖永久等待的修订测试改为在真实截止之前接收修订，迟到结果仍作废。

RMS能量后备独立标记，20/40ms起音暂缓、60ms确认仍保护讲话；既有600ms平稳底噪学习后撤回纯能量支持，缺失/故障VAD下不永久重置静音。真实VAD弱声通道保持，尚不能保证隔离强背景人声。

本地队列调度回归检查最多5包/100ms、50项且PCM最多1秒、原包顺序、端点/final/None占位、批内不能借未来人声授权、暂停/代际隔离及稳定partial只预览一次。云端活跃期间保持逐包observe→notify→accept，避免同批已返回的结果又重启等待看门狗；回退实际本地后才合批。

调度收益采用两种验证：确定性虚拟生产时钟中，每20ms产生一帧、每dispatch固定60ms时，逐帧达到50项溢出，合批全部250帧无丢失且峰值3项；本机一次5秒数字静音采样，逐帧381.3ms/250次调度，合批271.9ms/50次。后者仅本机单次结果，不证明所有负载改善29%，也未减少模型每帧推理本身。持续算力不足仍有界暂停，不允许越过未处理声音播报。

Chromium的no-result模拟云端先返回有效final，随后第二次有声无新文字；1000ms结果超时回退本地，约3000ms真实静音后自动发出下一段音频，不调用手动定位/提示。断言reading位置不变、reliable=false、原始文字未追加、提示来自保存起点。另验证1s轻量诊断、无实际PCM不得提前播报、断流5秒暂停，待处理声音优先。

## 本地ASR质量对照

2026-10-25在当前CPU环境，用同一组edge-tts合成中文、16kHz单声道PCM16，每20ms输入一次；直接读取原始模型输出，绕过讲稿校准。短句为“我将继续立足岗位，用心传递残疾人群体的心声。”（4.85秒、去标点20字），连续样本41.83秒、去标点178字。

| 权重与解码 | 短句字错误率 | 连续样本字错误率 |
|---|---|---|
| 全INT8、greedy | 55%（11/20） | 32.58%（58/178） |
| 全INT8、beam4 | 55% | 33.15% |
| INT8 encoder/joiner、FP32 decoder、greedy | 0% | 1.12%（2/178） |

原INT8和新FP32权重SHA-256均与发布者元数据一致，排除下载损坏。生产SpeechServices适配器再次验证短句0错误、长句2错误；确定性20dB白噪声小样本为0/20和1/178。这些是合成样本，不代表真人设备准确率，也不证明加噪声会改善识别。

新Docker镜像在无网络、无用户数据的临时容器复验，短句raw为“我将继续立足岗位用心传递残疾人群体的心声”，长句仍2/178。greedy策略保持，未用去重或脚本原文替换提高分数；FP32 decoder仅比旧decoder增加约0.8MB，保留INT8大encoder与joiner。

decoder文件decoder-epoch-99-avg-1.onnx大小13,876,452字节，SHA-256为2e3b5ec371f8899ee6acd829fd753ba45772df57a91bdf37cde3136354e7db7d。模型权重和合成语音不进入Git；原始对照为临时测试资产。

## 跨设备音频回归与验收

采集替身测试覆盖轨道采样率优先、默认率回退、刷新后的设备率、有界重试、失败图清理、模块与resume超时、取消、mute/ended、processorerror以及suspended/interrupted/closed。工作流另覆盖输出解锁失败时仍启动识别、输入失败保留诊断、立即暂停/继续时不复用已取消打开操作、同步采集失败不发送audio_ready、播放失败不发送playback_finished。

Chromium使用原生Web Audio与fake-device，验证输入报告48000Hz、图48000Hz、640字节帧，采集suspend后关闭旧图并可继续恢复；输出suspend后仅发送一次playback_failed、没有playback_finished，会话暂停并显示原因。未使用该测试测量真实音频质量或物理出声。

播放器测试覆盖解锁/解码超时与拒绝、已关闭Context重建、旧结果隔离、停止清理、播放中断和缺失ended；只有当前音源的正常ended可确认完成。8/16/22.05/32/44.1/48/96kHz合成输入的一秒均输出50个640字节帧，并验证第二声道与多声道混合。这只证明格式、时钟和生命周期，不证明抗混叠质量、真实人声准确率或物理扬声器可听。

目标设备需分别记录以下结果，不用“服务就绪”代替验收：

| 组合/场景 | 需要核对 |
|---|---|
| Windows/macOS桌面Chrome、Edge、Firefox | 系统输入设备、报告率与图率、连续朗读10分钟、暂停/继续和实际扬声器声音 |
| Android Chrome、iPhone/iPad Safari | 首次授权、用户点击解锁、切后台/回前台、锁屏/来电后返回并继续 |
| 内置、USB、蓝牙麦克风与耳机 | 输入/输出切换前后采样率和实际路由、断开重连、蓝牙通话模式带宽变化 |
| 输出失败 | 静音标签页、错误默认设备、系统中断、解码失败；确认不提前推进提示起点 |
| 识别准确率 | 同一段真人中文，安静/弱声/远讲/背景声分别记录原始ASR，不用讲稿对齐文字替代 |

当前自动化使用合成输入和模拟服务，未完成上述物理设备矩阵，不能宣称所有浏览器或设备均通过。

## 设备与部署验收

自动化不替代目标麦克风、耳机、读屏、弱声/远讲、键盘/风扇/音乐、背景讲话、回声和长时会话。记录误失锁、错误跳转、充分正文后的恢复率、恢复延迟与实际识别源。

真实云端需分别验证鉴权/协议、中文识别与模型生成权限；静音空音频响应只证明网络/协议。TTS依赖后端网络，浏览器播放需输出设备与授权。

部署验证另执行Compose配置、镜像构建与健康检查，步骤见[部署手册](../DEPLOY.md)。源码测试或清理不表示运行容器已经更新。
